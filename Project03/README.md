# Project03 - 찾아줘: 색상과 물건 등장 알림

“빨간 컵이 보이면 알려줘”라고 말하면, 카메라를 관찰하다가 종류와 색상이 모두 맞는 물건이 확인되는 순간 위치를 음성으로 알려 주는 프로그램이다. 대답을 듣기 위해 화면을 계속 보고 있지 않아도 된다.

## 프로젝트의 특징

- **나중에 실행하는 요청:** 지금 보이는 장면에 답하는 대신, 사용자의 조건을 기억하고 기다린다.
- **발견할 때만 알림:** 종류와 요청한 색상이 세 번 연속 확인되면 한 번만 말하고 찾기를 종료한다.
- **위치를 함께 설명:** “찾으시던 빨간 컵이 화면 왼쪽에 보입니다”처럼 안내한다.
- **모델 재사용:** YOLO와 Gemma를 시작할 때 한 번 불러온다. 이후 요청에서는 Gemma 로딩을 반복하지 않는다.

지원 물건은 `yolo.names`에서 자동으로 읽는다. 별도의 10종 제한은 없으며 기본 COCO 사전학습 모델은 80종을 지원한다([클래스 목록](https://docs.ultralytics.com/datasets/detect/coco/)). 한 번에 물건 하나와 선택적인 색상 하나를 찾는다.

지원 색상은 빨강, 주황, 노랑, 초록, 파랑, 보라, 흰색, 검정이다. “컵이 보이면 알려줘”처럼 색을 생략하면 종류만 확인한다. 분홍색이나 회색처럼 현재 기준에 없는 색은 등록하지 않도록 지시한다. 모델이 요청을 잘못 해석할 가능성은 남아 있다.

## 처리 순서

```text
v → 녹음 → 무음 검사 → Whisper → 같은 Gemma로 물건·색상 선택
                                      ↓
                               물건 이름과 색상 기억
                                      ↓
카메라 → 약 1초 간격 YOLO + 색상 확인 → 3회 연속 확인 → 위치 안내 → 찾기 종료
```

`main.py` 한 파일에서 실행한다. 카메라 화면은 메인 스레드가 처리하고, 녹음·Whisper·Gemma·음성 재생은 작업 스레드 하나가 처리한다. 요청을 해석하거나 음성을 재생하는 동안에도 미리보기를 계속 표시한다. 이때 YOLO 추론은 잠시 쉬어 CPU 부하와 중복 알림을 줄인다. 장비 자원이 부족하면 화면 FPS는 낮아질 수 있다.

## 제출 파일

- `main.py`: 음성 요청 등록, 물건 관찰, 발견 알림
- `camera_check.py`: 모델 없이 같은 pipeline의 카메라만 확인하는 진단 파일
- `config.json`: 모델 경로와 장치 설정
- `requirements.txt`: Python 패키지 의존성
- `presentation.md`: 발표 내용 원본
- `output/pdf/presentation.pdf`: 최종 제출용 발표 자료

`runtime/`에는 최근 녹음, 인식 텍스트, 응답 음성이 저장되고 덮어쓴다. Git에는 포함하지 않는다. 찾기 조건은 변수에만 저장하므로 프로그램을 종료하면 사라진다.

## 준비

수업에서 구성한 Jetson의 Python/PyTorch 환경과 GStreamer 지원 OpenCV를 사용한다. USB 카메라, 마이크와 스피커를 연결한다. Whisper.cpp 실행 파일과 모델, Piper 가상환경과 한국어 음성 모델, Gemma GGUF 파일은 별도로 준비한다. Piper의 `.onnx` 옆에는 `.onnx.json`도 있어야 한다. 녹음과 재생에는 `alsa-utils`의 `arecord`, `aplay`가 필요하다.

```bash
cd Project03
python3 -m pip install -r requirements.txt
```

위 명령만으로 Jetson용 CUDA 빌드나 모델 호환성이 구성되는 것은 아니다. 수업에서 검증한 패키지 환경을 사용한다. 모델 파일은 크기가 커 중복 포함하지 않았다.

### 설정

`config.json`의 상대 경로는 이 폴더 기준이다. 다른 위치에 설치했다면 절대 경로로 바꿔도 된다.

| 설정 | 설명 |
|---|---|
| `yolo_model` | 기본값은 저장소의 `../src/models/YOLO/yolo11n.pt` |
| `gemma_model` | 수업에서 사용한 Gemma GGUF 경로 |
| `whisper_cli`, `whisper_model` | Whisper 실행 파일과 한국어 인식 모델 경로 |
| `piper_python`, `piper_model` | Piper 가상환경의 Python과 한국어 음성 모델 |
| `camera` | 장치 번호. 0이면 `/dev/video0` 사용 |
| `mic_device`, `speaker_device` | ALSA 장치, 기본 `default` |
| `record_seconds` | 요청 녹음 시간, 기본 5초 |
| `silence_threshold` | 무음 검사 기준 소리 크기, 기본 200 |
| `confidence` | YOLO 신뢰도 기준, 기본 0.4 |
| `gpu_layers` | Gemma GPU 레이어 수. Nano용 기본값 0은 CPU 실행 |
| `context_window` | 지시문·클래스 목록·요청·답변을 포함하는 Gemma 한도, 기본 2048토큰 |
| `check_interval` | 관찰 시 탐지 간격, 기본 1초. 실제 간격에는 추론 시간도 더해짐 |
| `confirm_count` | 종류와 색상이 연속으로 맞아야 할 횟수, 기본 3회 |
| `color_min_ratio` | 물건 중앙 영역에서 요청 색상이 차지할 최소 비율, 기본 0.35 |

카메라는 기존 `yolotest.py`의 YUY2, 640×480, 30 FPS 입력을 유지한다. pipeline 안에서 320×240, 10 FPS로 줄여 프로그램에 전달한다. 카메라 자체의 USB 전송량까지 줄인 것은 아니다. 마이크와 스피커 번호는 `arecord -l`, `aplay -l`로 확인한다. 마이크가 card 3, device 0이면 `mic_device`는 `plughw:3,0`이다.

## 실행과 시연

```bash
cd Project03
python3 main.py
```

1. 처음 YOLO와 Gemma 로딩이 끝나면 카메라 창을 선택하고 `v`를 한 번 누르고 놓는다.
2. 안내가 나오면 “빨간 컵이 보이면 알려줘”라고 말한다.
3. 이미 불러둔 Gemma가 해석을 마치면 “빨간 컵이 보이면 알려드릴게요”라고 확인한다.
4. 빨간 컵을 화면 밖에 두었다가 카메라 왼쪽에 가져온다.
5. 세 번 연속 탐지되면 “찾으시던 빨간 컵이 화면 왼쪽에 보입니다”라고 한 번 알린다.
6. 파란 컵에는 알리지 않는지도 확인한다. 이후에는 같은 빨간 컵이 계속 보여도 추가로 말하지 않는다. 다시 찾으려면 `v`로 등록한다.

`h`는 지원 목록 출력, `c`는 찾기 취소, `q` 또는 `Ctrl+C`는 종료다. 새 유효 요청을 등록하면 기존 대상을 바꾼다. 무음이거나 지원하지 않는 요청이면 기존 찾기 상태를 유지한다. 요청 처리 중에는 새 `v` 입력을 무시한다. `c`를 누르면 현재 찾기와 아직 적용되지 않은 등록 결과를 취소한다. 이미 실행 중인 녹음·추론·음성 재생을 강제로 중단하지는 않는다. 종료 시 카메라 창은 닫고, 진행 중인 음성 작업이 끝나면 모델을 해제한다. 등록 시 이미 화면에 있는 물건도 세 번 연속 확인되면 알린다. 반드시 화면 밖에서 들어오는 변화만 감지하는 방식은 아니다.

### 지원 목록 확인

실행 중 카메라 창에서 `h`를 누르면 실제 YOLO 클래스 목록과 색상을 터미널에 출력한다. 시작할 때 같은 내용을 `Project03/runtime/supported_objects.txt`에도 저장한다. 이 목록은 현재 설정한 모델에서 읽은 것이므로 모델을 바꾸면 함께 달라진다. 기본 모델의 전체 클래스는 위 COCO 문서에서도 확인할 수 있다.

### 속도에 대해

첫 실행에서는 모델 로딩을 기다려야 한다. 다음 요청부터는 Gemma 로딩을 생략하지만 기본 5초 녹음, Whisper 인식과 Gemma 추론 시간은 여전히 필요하다. 정확한 지연 시간은 Nano에서 측정해야 한다. Gemma를 우회하는 단어 매칭은 사용하지 않아 과제의 요청 해석 역할을 유지했다.

## 설명할 코드

| 함수 또는 변수 | 역할 |
|---|---|
| `has_voice()` | 소리 크기 기준을 넘는 구간이 총 0.3초 이상인지 확인 |
| `speech_to_text()` | 녹음, 무음 검사, Whisper 인식 |
| `load_gemma()` | 시작 시 Gemma를 한 번 불러오기 |
| `choose_target()` | 같은 Gemma에 YOLO 목록과 요청을 전달해 물건·색상 JSON 받기 |
| `register_request()` | 작업 스레드에서 녹음과 요청 해석 수행 |
| `matches_color()` | 물건 중앙 영역의 HSV 색상 비율 확인 |
| `find_position()` | 종류와 색상이 맞는 박스를 찾고 화면상 위치 계산 |
| `text_to_speech()` | 정해진 안내 문장을 Piper로 만들어 재생 |
| `target` | 현재 찾을 물건. 없으면 관찰 추론을 하지 않음 |
| `found_count` | 연속으로 탐지한 횟수. 놓치면 0으로 초기화 |

찾는 조건은 긴 대화 기록이 아니라 아래처럼 작은 JSON이다. `object`는 YOLO 모델의 실제 클래스 목록과 비교하고 `color`는 코드의 색상 목록과 비교한다. `name`은 음성 안내를 위한 한국어 이름이다. 여러 물건, 미지원 색상, 주인이나 글자 같은 추가 조건은 등록하지 않도록 안내한다.

```json
{"object": "cup", "color": "red", "name": "컵"}
```

### 색상을 판단하는 방법

YOLO가 찾은 박스의 중앙 60% 너비·높이 영역을 잘라 BGR에서 HSV로 바꾼다. 배경의 영향을 줄이기 위해 가장자리를 제외한 것이다. 각 색의 HSV 범위를 `cv2.inRange()`로 검사하고, 해당 픽셀이 35% 이상이면 색상 조건이 맞는 것으로 본다. 빨강은 색상환 양 끝에 있어 두 구간을 합친다. 색상을 생략한 `any`는 이 검사를 건너뛴다. 방법은 [OpenCV 튜토리얼](https://docs.opencv.org/4.9.0/da/d97/tutorial_threshold_inRange.html)을 참고했다.

비율 기준은 정확도를 보장하는 값이 아니라 장비 시연을 위한 초기값이다. `color_min_ratio`를 높이면 더 엄격하게 검사한다. 박스는 물건 종류의 탐지 결과이며, 색상 조건이 맞아야 알림 횟수가 올라간다.

연속 확인은 같은 종류와 색상이 탐지되는지 세는 방식이며, 동일한 개체를 추적하는 기능은 아니다. YOLO는 대상 클래스만 결과로 받아오지만 내부 신경망 계산 전체가 대상 하나로 줄어드는 것은 아니다. 관련 인자는 [Ultralytics 문서](https://docs.ultralytics.com/modes/predict/)를 참고한다.

## Nano의 메모리와 한계

YOLO와 Gemma는 시작 시 한 번 로딩해 종료할 때까지 유지한다. Gemma는 요청이 올 때만 추론하고 평소에는 메모리에 대기한다. 요청마다 모델을 다시 로딩하는 시간을 줄이는 대신 관찰 중 RAM 사용량이 이전보다 커진다. 종료할 때 진행 중인 작업을 마친 후 `close()`로 Gemma 자원을 해제한다([API 문서](https://llama-cpp-python.readthedocs.io/en/latest/api-reference/)). 매 요청에는 같은 지시문과 이번 요청만 전달하며 이전 대화를 누적하지 않는다.

Gemma는 컨텍스트 2048, 배치 16, CPU 스레드 2개, 출력 최대 96토큰으로 설정했다. 이전 1024 설정은 전체 클래스 목록과 채팅 형식까지 포함하면 짧은 사용자 요청에서도 초과할 수 있어 지시문을 간결하게 줄이고 한도를 늘렸다. 실제 입력 토큰 수는 응답의 usage 정보가 있으면 터미널에 출력한다. 컨텍스트 증가는 추가 메모리를 사용한다. 모델 자체가 Nano의 메모리에 맞지 않으면 더 작은 호환 GGUF가 필요하다. 이 설정으로 실행을 보장하지는 않는다. 실제 사용량은 장비의 `free -h`, `tegrastats`로 확인한다.

작은 영상과 낮은 탐지 빈도 때문에 작은 물건이나 잠깐 지나가는 물건을 놓칠 수 있다. HSV 색상 검사는 조명, 반사, 배경, 여러 색이 섞인 물건에 영향을 받는다. 사람처럼 물건 표면만 정확히 분리하는 방식은 아니다. 무음 검사는 소리 크기 방식이므로 큰 주변 소음을 음성과 완벽히 구분하지 못한다. 소음을 요청으로 처리하면 `silence_threshold`를 높이고 작은 목소리를 놓치면 낮춘다. 무음의 잘못된 인식 사례는 [Whisper.cpp 이슈](https://github.com/ggml-org/whisper.cpp/issues/1724)를 참고했다.

카메라 읽기는 연속 3회 실패하면 종료한다. 장치 번호, GStreamer 지원, USB 연결, 전원과 지원 영상 형식을 확인한다. PulseAudio 점유 문제라면 수업에서처럼 `pasuspender -- python3 main.py`로 실행한다. 실제 카메라와 모델을 사용한 장비 시연 및 성능 측정은 별도로 진행한다.

## 요청 전에도 화면이 멈출 때

`v`를 누르기 전에는 YOLO 추론과 음성 처리를 하지 않는다. 이때도 화면이 멈추면 카메라 수신, 화면 표시, 또는 모델을 유지하는 데 따른 시스템 자원 문제를 구분해야 한다.

기존 프로그램을 종료한 뒤 다음 명령으로 같은 카메라 pipeline만 30초 정도 실행한다. 두 프로그램을 동시에 켜면 카메라를 함께 점유할 수 있으므로 하나씩 실행한다.

```bash
cd Project03
python3 camera_check.py
```

진단 화면에서도 멈추면 카메라·USB·pipeline·화면 표시 쪽을 먼저 확인한다. 진단은 정상인데 일반 실행만 멈추면 두 모델이 올라간 상태의 RAM·SWAP·CPU 사용량을 확인한다. 일반 실행은 모델 로딩 전후 메모리와 1초 이상 걸린 카메라 수신·화면 갱신 구간을 출력한다. 지연 시간에는 운영체제가 프로세스 실행을 미룬 시간도 포함될 수 있어 해당 로그만으로 드라이버 문제라고 단정하지 않는다.

장비의 별도 터미널에서 `tegrastats`로 멈추는 순간 RAM과 SWAP을 함께 확인한다. SWAP 사용이 늘어났다는 것만으로 원인이 확정되지는 않는다. 실제 측정 결과를 비교한 뒤 모델이나 카메라 설정을 조정한다.

## 계속 무음으로 판단될 때

프로그램을 다시 시작한 뒤 녹음 안내의 장치, 무음 기준, 설정 파일 경로를 확인한다. 설정은 시작할 때 한 번 읽으므로 실행 중 파일만 수정하면 적용되지 않는다. 녹음 후에는 최대 RMS와 기준을 넘긴 시간이 출력된다.

```text
녹음 확인: 최대 RMS=..., 기준=200, 기준 이상=...초 (필요: 0.30초)
```

최대 RMS가 거의 0이면 먼저 마이크 장치와 입력 음소거 여부를 확인한다. 값이 200보다 작으면 마이크 입력 볼륨과 거리를 확인한다. 최대값이 충분해도 기준 이상 시간이 0.3초 미만이면 짧은 소리로 판단한 것이다.

최근 녹음 자체도 장비에서 재생해 본다.

```bash
aplay Project03/runtime/input.wav
arecord -l
```

위 경로는 저장소 최상위에서 실행할 때 기준이다. 녹음에 목소리가 없으면 기준값만 낮추기보다 `mic_device`를 실제 마이크 장치로 지정한다. 재생 장치 설정 문제가 있을 수 있으므로 스피커가 정상 동작하는지도 함께 확인한다.

### 지원 목록과 모델 크기의 관계

이전의 10종 제한은 프로그램에서 정한 범위였으며 메모리를 줄이기 위한 처리는 아니었다. 지금은 모델의 클래스 목록을 자동으로 사용한다. `classes`로 결과를 제한해도 모델의 가중치 크기는 그대로다. Nano의 부담은 모델 종류, 입력 크기, 추론 빈도와 Gemma 로딩에 영향을 받는다. 기본 모델이 학습하지 않은 물건은 목록에 이름만 추가해서 탐지할 수 없으며, 별도의 학습이나 다른 모델이 필요하다.
